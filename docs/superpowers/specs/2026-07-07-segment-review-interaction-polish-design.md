# 片段审核交互收敛设计

## 背景

当前“文本产物”区域已经具备片段级审核闭环，但在实际交互上还有三处不一致：

- 点击 `确认` 后，片段会额外显示 `已确认` 标签，打断正文浏览
- `未处理` 统计与筛选把普通片段也算了进去，和“疑似错误片段”语义不一致
- 点击 `确认` 后只有顶部状态条变化，右侧详情区仍可继续操作，容易让用户误以为没有生效并重复点击

本次迭代只收敛上述交互语义，不修改后端审核协议。

## 目标

1. 让“未处理”的定义与“疑似错误片段”保持一致
2. 让已确认片段回归普通正文视觉，减少冗余标签
3. 为 `确认` 操作补充局部 loading 和交互锁定，降低重复提交风险

## 非目标

- 不修改 Python 引擎的 `update_segment_review` 协议
- 不新增新的审核状态
- 不移除普通片段的手动修正能力
- 不调整导出逻辑和任务存储结构

## 核心规则

### 片段分类

片段是否属于“未处理”，统一定义为：

- `needsReview === true`
- 且 `reviewStatus === "pending"`

这意味着：

- 只有带 `疑似错误片段` 的重点片段，才会被计入 `未处理`
- 普通片段即使默认 `reviewStatus = pending`，也不再进入“未处理”

### 状态展示

#### `needsReview === true` 且 `reviewStatus === "pending"`

- 片段正文显示 `疑似错误片段`
- hover 时显示：
  - `确认`
  - `修正`

#### `needsReview === true` 且 `reviewStatus === "confirmed"`

- 不显示 `已确认` 标签
- 不显示 `疑似错误片段`
- hover 时仅显示：
  - `修正`

#### `reviewStatus === "corrected"`

- 保持当前 `已修正` 标签
- hover 时显示：
  - `再修正`

#### `needsReview === false`

- 不显示 `疑似错误片段`
- 不显示 `确认`
- hover 时显示：
  - `修正`

## 工具栏规则

### `未处理 X`

`未处理 X` 的计数来源改为：

- 当前最终文本中
- `needsReview === true`
- 且 `reviewStatus === "pending"`

### `仅看重点`

继续显示：

- `needsReview === true`
- 且 `reviewStatus === "pending"`

### `仅看未处理`

与上面的“未处理”定义完全一致，也只显示：

- `needsReview === true`
- 且 `reviewStatus === "pending"`

这次调整后，`仅看重点` 与 `仅看未处理` 在结果集合上等价，但先不删除任一入口，避免同时变更过多界面结构。

## Loading 与交互锁定

### 触发时机

点击片段 `确认` 按钮后，前端立即进入“右侧详情区忙碌中”状态，直到请求完成或失败。

### 覆盖范围

busy 状态覆盖右侧整列内容：

- 任务详情
- 运行状态
- 音频播放器
- 文本产物

左侧任务列表与全局刷新能力保持现状，不纳入本次锁定范围。

### 交互要求

busy 状态期间：

- 右侧所有按钮不可点击
- 片段列表不可继续触发跳转与审核操作
- 导出下拉不可展开
- 播放器不可继续拖动或点击
- 文本区域不可继续进入编辑态

busy 结束后恢复原有交互。

### 视觉反馈

在保留顶部 `正在保存确认结果` 状态文案的同时，右侧详情区新增局部遮罩：

- 半透明覆盖层
- 中央轻量 loading 指示
- 文案使用类似 `正在确认片段…`

目标是明确告诉用户“请求已收到，当前区域暂不可操作”。

## 实现边界

### `renderer.js`

需要收敛三类判断：

- 什么算 `未处理`
- 什么场景显示 `确认`
- 什么场景显示审核标记

同时新增右侧 busy 状态的切换逻辑，并在 `确认` 请求生命周期里挂接开启与关闭。

### `index.html`

需要补充：

- 右侧内容容器的定位层级
- busy 遮罩 DOM
- 遮罩、loading、禁用态样式

## 风险与取舍

### `仅看重点` 与 `仅看未处理` 暂时重复

这会保留两个语义接近的入口，但这是有意取舍：

- 当前用户只要求修正统计和确认交互
- 如果本次顺手删除或重命名入口，会把局部交互修正扩大成信息架构调整

后续如果继续精简工具栏，再单独评估是否合并两者。

### `已修正` 仍然保留标签

本次只去掉 `已确认` 标签，不同步去掉 `已修正`。原因是：

- “确认”代表无改动，适合回归普通正文视觉
- “修正”代表文本已被人工改写，保留显式提示更有价值

## 验收标准

1. 普通片段 `needsReview === false` 时，不显示 `疑似错误片段`
2. 普通片段不显示 `确认`，但 hover 后仍可见 `修正`
3. `未处理 X` 只统计 `needsReview === true && reviewStatus === "pending"` 的片段
4. `仅看未处理` 不再显示普通片段
5. `仅看重点` 继续只显示待处理的重点片段
6. 点击 `确认` 后，片段不再显示 `已确认` 标签
7. 已确认片段 hover 后仅显示 `修正`
8. 点击 `确认` 后，右侧详情区立即出现 loading 遮罩
9. loading 期间右侧详情区不能继续点击、拖动或展开导出
10. 请求完成或失败后，右侧详情区自动恢复交互
