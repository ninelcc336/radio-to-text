# 任务选中与处理入口交互调整设计

## 概述

当前桌面端的任务创建与处理交互有三个体验问题：

- 选择音频创建任务后，虽然前端状态会更新，但用户对“当前任务是否已切换到新任务”的感知不够直接。
- `处理当前任务` 按钮固定放在左侧操作区，与右侧任务详情的“当前状态”信息分离，任务主操作入口不够聚焦。
- 任务进入处理中时，缺少明显的右侧详情 loading 反馈，用户不容易判断当前是否正在执行转写。

本次调整的目标是在不改动后端协议的前提下，收敛任务创建、任务处理和处理中状态反馈，让右侧任务详情成为当前任务的主操作区。

## 目标

- 创建任务成功后，自动选中新任务，并立即在右侧展示该任务详情。
- 把左侧 `处理当前任务` 按钮移除。
- 把右侧待处理状态下的主操作按钮改成 `转录文本`，并放入“当前状态”区域。
- 当任务处于处理中时，为右侧详情区添加遮罩式 loading 效果。
- 保持现有 `process_task` 请求协议和任务状态字段不变。

## 非目标

- 本次不改 Python 引擎协议。
- 本次不调整任务列表的排序规则。
- 本次不新增任务处理中断、取消或重试能力。
- 本次不对左侧任务列表增加自动滚动行为。

## 推荐方案

推荐继续复用现有前端的 `selectedTaskId`、任务详情渲染函数和右侧忙碌遮罩层，在 `renderer.js` 内集中收敛这三类交互。

原因如下：

- 当前任务切换逻辑已经围绕 `selectedTaskId` 组织，不需要再引入新的前端状态源。
- 右侧“任务信息”区域已经有“当前状态” banner，适合承接待处理时的主按钮和处理中视觉反馈。
- `detail-busy-overlay` 已经存在，直接扩展为“审核忙碌或任务处理中都可用”比重新做全局 loading 成本更低。

## 交互设计

### 1. 创建任务后的选中行为

当用户点击“选择音频并创建任务”并成功导入后：

- 前端立即将新返回任务的 `task_id` 设为当前选中任务。
- 左侧任务列表同步渲染选中态。
- 右侧详情、播放器和文本区域立即切换到该任务。

本次只做“自动选中并展示右侧详情”，不增加“自动滚动任务列表到该任务”的行为。

### 2. 处理按钮迁移

左侧操作卡中的：

- `处理当前任务`

需要移除。

右侧“任务信息”中的“当前状态”区域在以下条件下显示主按钮：

- `task.status === "ready"` 时显示
- 如现有创建后状态仍可能是 `created`，则也允许显示，避免状态兼容问题

按钮文案统一改为：

- `转录文本`

按钮点击后仍然调用现有：

- `process_task`

即业务语义不变，只调整入口位置和展示文案。

### 3. 处理中 loading

当当前选中的任务状态为：

- `processing`

右侧详情区显示遮罩式 loading，覆盖范围包括：

- 任务信息
- 音频播放器
- 文本产物

loading 文案应尽量使用当前阶段信息映射，例如：

- `preprocessing` -> `正在预处理音频...`
- `transcribing` -> `正在转写文本...`
- `diarizing` -> `正在识别说话人...`
- `exporting` -> `正在整理导出结果...`
- 其他处理中阶段 -> `正在处理任务...`

处理中时：

- “当前状态”区域不再显示 `转录文本` 按钮
- 右侧详情区不可交互

处理完成或失败后：

- 右侧遮罩自动消失
- 详情区恢复可交互状态

## 实现边界

主要修改以下文件：

- `app/desktop/renderer/index.html`
- `app/desktop/renderer/renderer.js`

实现原则：

- 不改 `preload.js` 和主进程 IPC。
- 不改 Python 侧任务状态生成逻辑。
- 复用现有 `detail-busy-overlay` 样式与 DOM，仅扩展其触发来源。

## 前端状态策略

右侧详情区的 busy 来源统一收敛为两类：

- 审核操作中的局部忙碌状态
- 当前选中任务本身处于 `processing`

渲染优先级：

1. 如果审核操作正在进行，优先展示审核相关 busy 文案。
2. 否则如果当前任务处于 `processing`，展示任务处理中 busy 文案。
3. 否则关闭右侧 busy 遮罩。

这样可以避免两个来源互相覆盖或闪烁。

## 测试与验收标准

本次落地后，至少应满足以下验收标准：

- 选择音频并创建任务后，新任务自动成为左侧选中项。
- 创建成功后，右侧立即展示该新任务的任务信息、播放器状态和文本区域。
- 左侧不再显示 `处理当前任务` 按钮。
- 右侧“当前状态”在待处理任务下显示 `转录文本` 按钮。
- 点击 `转录文本` 后，前端继续调用现有 `process_task`。
- 当前任务进入 `processing` 后，右侧显示遮罩式 loading。
- 处理完成或失败后，右侧 loading 自动消失。

## 风险与后续

当前主要风险：

- 如果任务状态从 `created` 到 `ready` 的切换在不同入口上不完全一致，按钮显示条件需要兼容两种状态。
- 右侧 busy 遮罩现在既服务审核动作又服务任务处理，状态合并时需要避免文案与开关逻辑打架。

建议的实现顺序：

1. 先迁移按钮并调整任务创建后的自动选中逻辑。
2. 再把右侧 busy 遮罩扩展到任务处理中场景。
3. 最后做一次完整手动验证，确认创建、处理和处理完成三段状态切换流畅。
