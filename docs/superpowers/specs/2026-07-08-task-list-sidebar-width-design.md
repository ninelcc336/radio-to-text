# 任务列表左栏宽度修复设计

## 背景

Next 渲染层迁移后，左侧任务栏在桌面常规窗口宽度下使用固定 `320px` 栏宽。任务列表卡片同时承载任务名、来源信息、状态标签和任务 ID，在滚动区域内显示时，右侧视觉空间过紧，出现“卡片像被遮住一部分”的感受。

本次调整目标是修复左栏显示拥挤问题，让任务卡片在左侧栏内完整、稳定地展示，同时避免明显压缩右侧详情区。

## 目标

1. 增加左侧任务栏在桌面布局下的可用宽度
2. 避免任务卡片贴着滚动条边缘，产生被遮挡的视觉效果
3. 保持现有任务卡片结构、交互和信息层级不变
4. 不影响首页与任务详情页共用的壳层布局

## 非目标

- 不重做任务卡片内容排版
- 不修改任务列表筛选、导入、重命名、删除交互
- 不改变移动端或小屏下的堆叠布局逻辑
- 不调整右侧详情页内部组件宽度策略

## 方案对比

### 方案 A：仅把左栏固定宽度从 `320px` 提高到更大数值

优点：

- 改动最少
- 仅需调整壳层主栅格列宽

缺点：

- 窗口变窄时缺少弹性
- 只能缓解，不处理滚动区边缘的视觉压迫

### 方案 B：把左栏改为响应式更宽列宽

做法：

- 将桌面布局列宽从固定 `320px` 调整为 `minmax(360px, 400px)` 一类的响应式范围

优点：

- 常规桌面宽度下更宽
- 窄一些的桌面宽度下仍可适度回收空间

缺点：

- 仍未直接处理滚动区右边缘的拥挤感

### 方案 C：响应式加宽左栏，同时为任务列表滚动区补右侧安全空间

做法：

- 壳层主布局改为响应式更宽的左栏
- 任务列表滚动区补齐右侧留白，避免卡片视觉上贴近滚动条

优点：

- 同时解决“左栏太窄”和“右侧像被遮挡”的叠加问题
- 只涉及样式层，风险低

缺点：

- 改动点比单纯加宽略多，但仍然集中在前端布局文件

## 推荐方案

采用方案 C。

原因：

- 当前问题不是单一组件缺陷，而是左栏宽度与滚动容器边缘空间共同造成的结果
- 任务列表首页和详情页共用同一个壳层，使用响应式更宽的左栏可以一次性改善两个入口
- 仅修布局，不碰任务卡片内容和业务逻辑，回归风险较低

## 实现设计

### 1. 壳层主布局

调整 `app-shell.tsx` 中桌面主栅格的列定义：

- 当前：左栏固定 `320px`
- 调整后：左栏使用响应式较宽列宽，右侧继续保持 `minmax(0, 1fr)`

预期效果：

- 左栏在常规桌面宽度下明显更宽
- 右侧详情区仍然保留弹性，不会被固定死宽度

### 2. 任务列表滚动区

调整 `task-list-panel.tsx` 中任务列表 `ScrollArea` 的右侧安全空间：

- 保证滚动条与卡片主体之间留有可感知间距
- 避免卡片边缘被滚动条区域“吃掉”的视觉效果

本次不改 `TaskListItem` 组件结构，只通过容器层解决显示问题。

## 影响文件

- `app/desktop/web/components/app-shell.tsx`
- `app/desktop/web/components/tasks/task-list-panel.tsx`

## 验收标准

1. 首页左侧任务列表在桌面常规窗口宽度下明显比当前更宽
2. 任务详情页左侧任务列表同步获得相同宽度优化
3. 任务卡片右边缘不再出现明显“被遮住一截”的观感
4. 右侧详情主内容区仍可正常显示，不出现整体挤压变形
5. 任务列表滚动、筛选、导入和卡片点击行为保持不变

## 验证方式

1. 运行桌面端并进入首页，观察左侧任务列表卡片显示
2. 打开任一任务详情页，确认共用壳层下左栏宽度一致
3. 手动滚动任务列表，确认滚动条不再贴住卡片主体
4. 至少运行一次 `npm run smoke`
