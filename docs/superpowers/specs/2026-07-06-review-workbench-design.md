# 前端重点核对工作台设计

## 背景

当前仓库已经具备以下与复核相关的后端能力：

- `task.results.raw_segments`：原始转写片段
- `task.results.segments`：清洗后的转写片段
- `needs_review` / `review_reasons`：片段级复核标记
- 音频播放器与按片段跳转：用户可点击句段定位音频

现阶段的短板不在转写主链路，而在前端复核体验：

- 页面只能展示清洗后的片段，无法切回原始识别文本
- 待复核片段虽然已高亮，但无法快速过滤
- 没有待复核计数与上一条/下一条跳转
- 复核路径仍然依赖人工滚动查找，效率偏低

因此，本次迭代的目标是把已有结构化结果转成一个可用的“重点核对工作台”。

## 目标

在不改动任务数据结构、不重做页面布局的前提下，为桌面端增加一套轻量但完整的复核体验，使用户可以：

- 在原始文本与清洗文本之间切换
- 只查看待复核片段
- 快速定位上一条/下一条待复核内容
- 在当前任务内完成“看问题片段 -> 听音频 -> 核对文本”的闭环

## 非目标

本次不做以下内容：

- 不增加新的后端任务字段或 IPC 协议
- 不修改导出文件格式和导出策略
- 不新增“已复核/未复核”持久化状态
- 不做侧边复核面板或多列审校布局
- 不增加批量操作、批注、人工编辑保存

## 方案选择

### 方案 A：轻量复核工具条

在“文本产物”区域顶部增加一个紧凑工具条，包含：

- 文本版本切换：`清洗文本` / `原始文本`
- 过滤切换：`全部片段` / `仅待复核`
- 待复核计数
- `上一条` / `下一条` 跳转

优点：

- 与当前页面结构兼容
- 只依赖已有任务结果
- 改动集中在渲染层，风险低

缺点：

- 导出版本切换不在本轮范围内

### 方案 B：工具条 + 导出版本联动

在方案 A 基础上，让导出按钮同时支持导出原始文本或清洗文本。

优点：

- 查看和导出保持一致

缺点：

- 需要把当前视图状态传给导出逻辑
- 本轮改动范围会从渲染层扩展到导出行为

### 方案 C：完整审校面板

新增独立复核区，按问题片段建立单独列表，并支持后续状态记录。

优点：

- 可扩展性强

缺点：

- 超出当前项目节奏
- UI 与状态复杂度显著上升

### 推荐方案

采用方案 A。

原因是当前产品的主要短板在“找问题片段太慢”，而不是“导出维度不够丰富”。方案 A 能以最小改动形成闭环，并且为下一轮导出版本联动保留空间。

## 页面结构设计

### 文本产物区域

保留现有卡片结构，在标题右侧的现有工具区中扩展为两层信息：

- 第一组：复制、下载 TXT、下载 Markdown
- 第二组：复核工具

复核工具包括：

- 文本版本切换按钮组
- 过滤切换按钮组
- 待复核计数展示
- 上一条 / 下一条按钮

为了避免布局扩散，所有按钮保持当前紧凑工具栏风格，只新增少量区分状态的视觉样式。

## 前端状态设计

新增一个本地视图状态对象，用于管理当前文本展示模式：

- `textVersion`
  - 可选值：`clean`、`raw`
- `reviewFilter`
  - 可选值：`all`、`review-only`
- `activeReviewCursor`
  - 当前定位到的待复核片段在过滤结果中的索引

这些状态只存在于渲染层，不写入任务文件。

切换任务时重置为默认值：

- `textVersion = clean`
- `reviewFilter = all`
- `activeReviewCursor = -1`

这样可以避免不同任务之间复用上一个任务的复核视图状态，减少认知混乱。

## 数据映射设计

### 展示数据来源

根据 `textVersion` 决定读取的结果集：

- `clean`：`task.results.segments`
- `raw`：`task.results.raw_segments`

### 过滤规则

根据 `reviewFilter` 对当前结果集做二次筛选：

- `all`：展示全部片段
- `review-only`：只展示 `needs_review === true` 的片段

### 待复核计数

待复核计数基于当前文本版本对应的完整结果集计算，而不是基于过滤后的当前列表计算。

这样用户在切换到 `仅待复核` 前后看到的计数保持一致，避免把“当前列表长度”和“当前版本下问题片段总数”混为一谈。

## 交互流程设计

### 文本版本切换

用户点击 `清洗文本` 或 `原始文本` 后：

1. 更新 `textVersion`
2. 重新计算当前结果集
3. 保持当前过滤模式
4. 重绘片段列表
5. 重置 `activeReviewCursor`

### 仅待复核过滤

用户点击 `仅待复核` 后：

1. 更新 `reviewFilter`
2. 用当前文本版本的数据重新筛选
3. 若筛选结果为空，显示空状态
4. 若有结果，渲染待复核片段列表
5. 将 `activeReviewCursor` 重置为首条或未选中状态

### 上一条 / 下一条跳转

按钮操作基于当前文本版本下的待复核片段列表，而不是基于全部片段列表。

点击后行为：

1. 更新 `activeReviewCursor`
2. 找到对应片段
3. 自动滚动到该片段
4. 触发现有 `jumpToSegment(...)` 跳音频

当没有待复核片段时：

- 两个按钮禁用
- 页面展示明确空状态提示

### 片段点击

即使处于 `仅待复核` 模式，点击片段仍沿用当前的音频跳转行为，不新增分支逻辑。

## 渲染与代码组织

### `renderer.js`

建议新增或拆分以下辅助函数：

- `getTranscriptViewState()`
- `setTranscriptViewState(...)`
- `getActiveTranscriptSegments(task)`
- `getReviewSegments(segments)`
- `renderTranscriptToolbar(task)`
- `renderTranscriptContent(task)`
- `renderReviewEmptyState(message)`
- `focusTranscriptSegment(index)`
- `jumpToAdjacentReviewSegment(direction)`

目标是把“取数据”、“算过滤结果”、“渲染按钮”、“跳转逻辑”拆开，避免继续把所有状态逻辑堆在 `renderTask(...)` 和 `renderTranscriptSegments(...)` 里。

### `index.html`

只做结构性增量修改：

- 在 `output-toolbar` 区域加入复核控件容器
- 为版本切换、过滤切换、计数、导航按钮提供独立节点

### 样式

沿用现有暖色系视觉语言：

- 当前激活的切换按钮使用深一点的强调色
- 待复核计数采用轻提示色块
- 禁用的导航按钮降低透明度，不移除

## 错误处理与边界情况

### 没有任务

- 工具栏隐藏
- 文本区显示 `尚无转写结果。`

### 任务无转写结果

- 工具栏隐藏
- 不渲染复核按钮组

### 没有待复核片段

- 计数显示 `待复核 0`
- `仅待复核` 模式下显示 `当前文本版本下没有待复核片段。`
- `上一条` / `下一条` 按钮禁用

### 原始与清洗片段数量不一致

前端不假定两者长度一致，只使用当前版本对应的片段数组进行渲染和跳转。

### 音频不可播放

即使复核列表存在，也保留现有错误提示：

- 点击片段时提示“当前任务没有可播放音频”

## 测试与验收

### 脚本验证

至少运行：

- `npm run smoke`

如果已有样例任务可直接打开，则优先复用样例任务做手工验证。

### 手工验收标准

1. 打开已有任务时，默认展示清洗文本片段。
2. 切换到原始文本后，页面展示 `raw_segments` 内容。
3. 点击 `仅待复核` 后，只展示 `needs_review=true` 的片段。
4. 待复核计数与当前文本版本下的实际问题片段数一致。
5. 点击 `上一条` / `下一条` 时，页面会定位到目标片段并跳转音频。
6. 当当前文本版本下没有待复核片段时，页面显示空状态，导航按钮禁用。
7. 从 `仅待复核` 切回 `全部片段` 后，完整列表恢复，原有高亮能力保持正常。
8. 切换任务后，文本版本和过滤状态重置为默认值。

## 实施边界

本设计完成后，前端将具备基础复核工作台能力，但仍有以下留白：

- 导出原始文本或清洗文本的显式选择
- 待复核片段的人工确认状态
- 文本内联修改与保存
- 说话人视图下的同等复核能力

这些能力应作为后续独立迭代处理，不在本次实现范围内扩展。
